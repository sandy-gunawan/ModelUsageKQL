Azure Monitor / Ringkasan setup

Setup monitoring Foundry

Pusatkan log pemakaian model dan trace di satu Log Analytics workspace (LAW).

  1. Pilih satu LAW pusat. Gunakan workspace yang sudah ada.
  2. Hubungkan project ke satu Application Insights. Tautkan resource Insights itu ke LAW pusat.
  3. Atur Diagnostic settings di tiap resource Foundry. Kirim AzureOpenAIRequestUsage dan RequestResponse ke LAW yang sama.
  4. Jalankan KQL lab di LAW → Logs setelah ada trafik. Pakai query yang sama di Workbook untuk menampilkan tabel.

Application Insights untuk tracing. Query token tetap membaca log dari Diagnostic settings.

01. Atur log yang dikirim

Resource Foundry → Monitoring → Diagnostic settings

  1. Pilih Add diagnostic setting di resource Foundry, bukan di halaman project.
  2. Pilih Azure OpenAI Request Usage dan Request and Response Logs.
  3. Pilih Send to Log Analytics workspace dan gunakan workspace yang akan dibaca Workbook.

Kalau pengaturan yang sama sudah ada, cek dulu tujuan dan kategorinya sebelum menambah setting baru.

Lihat sumber bukti lab

Contoh KQL · Bukan screenshot portal

Ada log yang masuk?

AzureDiagnostics
| where TimeGenerated > ago(24h)
| where ResourceGroup =~ "rg_demo_pamadigi"
| where ResourceProvider =~ "MICROSOFT.COGNITIVESERVICES"
| where Category in (
    "AzureOpenAIRequestUsage", "RequestResponse"
)
| summarize Jumlah = count() by Category
AzureOpenAIRequestUsage
Catatan token yang dipakai model.
RequestResponse
Konteks request yang bisa dicocokkan, jika tercatat.

02. Cek sebelum buka Workbook

Log Analytics workspace → Logs

  1. Pilih workspace yang sama dengan tujuan log di tahap 01.
  2. Jalankan contoh KQL setelah ada request ke model. Sesuaikan 24h dengan periode trafik.
  3. Cek kategori yang muncul. Query ini menghitung baris log, bukan jumlah request unik.

Kalau hasil kosong, cek workspace tujuan, rentang waktu, dan apakah log sudah masuk. Jangan langsung menyimpulkan pemakaian nol.

03. Baca token dan estimasi

Log Analytics workspace → Workbooks → Edit

Tempel KQL terbaru dengan sumber Logs, workspace yang sama, dan tampilan Grid.

  1. Pilih Run Query saat periode query mencakup trafik.
  2. Baca Grid hasil: kolom model, project jika tercatat, dan total token. Periksa StatusHarga sebelum memakai EstimasiUSD.

Pakai screenshot lama untuk mengenali tombol dan grid. Untuk kolom estimasi dan status harga, lihat hasil KQL terbaru di bawahnya.
